# HabitRat 产品设计指南

> 本文档用于给 Claude Code（或其他协作者）提供项目背景和设计方向，作为后续视觉、文案、功能开发的统一依据。

---

## 1. 产品概述

**HabitRat（好习惯大冒险）** 是一个面向孩子的习惯打卡Web应用，核心机制是"打卡获得经验值/金币 → 升级 → 装扮吉祥物/场景"。

- **目标用户年龄段**：10-12岁（小学高年级）为主，理想覆盖到初中生（青少年）
- **产品定位**：不做成"低幼可爱"风格，而是做成这个年龄段孩子也愿意用的、有质感的"酷"产品
- **当前阶段**：小范围家庭试用中，尚未正式推广，正处于产品深度打磨期
- **商业定位**：作者认真经营的副业方向，非纯个人玩具项目

**已有核心功能**：打卡记录（周/月视图）、EXP与金币双激励、等级系统、商店兑换、家庭码跨设备同步、家长PIN、数据备份、打印周表。

---

## 2. 核心设计原则：这个年龄段的孩子要什么

10-12岁及以上孩子的关键心理：**抗拒"幼态"设计**，"这是给小孩玩的"是这个年龄段最忌讳的评价。因此：

- ❌ 避免：大量可爱emoji堆砌、"宝贝"这类称呼、"加油鸭"式儿童化语气、纯卡通扁平萌系画风
- ✅ 追求：游戏化的"任务/关卡/成就"语言、精致有质感的视觉风格、通过努力"变强/变自信"的成长反差感

**风格参考基调**：类似《原神》角色设计、《明日方舟》干员立绘的"精致奇幻写实"——写实的光影和材质，但线条干净、色彩讲究，**没有脏乱/惊悚的负面细节**。也可参考游戏《双影奇境（It Takes Two / Split Fiction 系列）》的魔幻+精致美术方向。

## 3. 吉祥物：小瑞（Ratty）

### 3.1 人物设定（保留，无需改动）

- **名字**：小瑞（Ratty）
- **角色**：习惯教练 & 成长伙伴
- **性格**：坚韧、善良、责任心强、乐于助人
- **爱好**：记录目标、帮助朋友、收集徽章
- **口头禅**："再来一次！""我能做到！""一点点就好"
- **背景故事**：一只经历过风雨、依然坚持的小老鼠，背着装着"习惯清单和梦想"的小书包，帮助孩子养成好习惯，自己也一点点变得更强大

### 3.2 视觉风格 —— ✅ V1 已定稿（Ratty_new1.png）

新版三视图+成长阶段图已通过确认，方向正式定稿。核心变化：

| 旧版问题 | V1 定稿方案 |
|---|---|
| 脏污质感 | 护甲干净整洁，材质写实但无脏乱感 |
| 暗色调，细节易糊 | 深色底+高饱和点缀色（发光蓝符文、金色金属），提升高级感和小尺寸可辨识度 |
| 装备简单（麻布、绳子） | 护甲纹路、符文、金属配件光泽，"冒险者装备"质感 |
| 成长阶段反差弱 | Lv.1 简陋皮甲、姿态青涩 → Lv.MAX 黄金铠甲+法杖+全身光效，反差显著 |
| 破损耳朵=脏乱破洞 | ⚠️ 待定：V1中耳朵伤痕细节已移除，是否在后续版本重新加入"经历风雨的印记"（处理成干净的裂纹/勋章式疤痕），待作者决定 |

**成长阶段命名（V1新版，替换原"XX鼠"谐音命名）：**

| 等级 | 称号 | 关键词 |
|---|---|---|
| Lv.1 | 新手冒险者 | 初入旅程 / 装备简陋 / 暗显疲惫 / 正在学习 |
| Lv.5 | 坚毅探险家 | 开始坚持 / 逐渐适应 / 更有信心 / 不再放弃 |
| Lv.10 | 勇敢挑战者 | 迎接挑战 / 勇敢前行 / 帮助他人 / 收获成长 |
| Lv.20 | 荣耀守护者 | 守护伙伴 / 能力提升 / 影响更多人 / 成为榜样 |
| Lv.MAX | 传奇领航者 | 光芒闪耀 / 引领方向 / 实现梦想 |

**表情/动作资产（V1已产出）**：思考、开心、加油、记录、胜利

**配色方案（正式定稿，供全App视觉统一使用）：**

| 色值 | 用途参考 |
|---|---|
| `#A38F7A` | 皮革/木质中性色 |
| `#5C6F8E` | 蓝灰主色（护甲/背景） |
| `#2D3340` | 深色背景基调 |
| `#C89D4A` | 金色点缀（勋章/高等级装备） |
| `#4FC3FF` | 发光蓝（符文/科技感点缀，核心识别色） |

**设计关键词**：坚持 Persistence / 成长 Growth / 勇气 Courage / 善良 Kindness / 探索 Explore

**装备图标集（V1已产出，可直接作为装扮系统道具的设计语言基础）**：冒险者徽章、符文护肩、多功能腰带、探险背包、习惯笔记本 —— 这5个图标风格统一、有分类感（配饰/护甲/腰带/背包/道具），装扮系统后续设计新道具时应延续这套图标语言（材质：皮革+金属+发光符文石）。

**品牌延展已验证可行**：App图标、成就徽章、贴纸、习惯手册封面 —— 说明这套视觉在不同应用场景下都能保持辨识度和质感。

### 3.3 技术产出要求（重要，直接影响后续开发可行性）

不管走哪种美术风格，都需要满足：

1. **角色三视图 + 5个成长阶段（新生鼠/坚持鼠/勇敢鼠/梦想鼠/闪耀鼠）+ 基础表情包（开心/坚定/思考/倦怠/加油/满足）**，风格必须严格一致（AI多次生成容易跑偏，需要建立可复现的提示词/参考图锁定风格）
2. **角色主体与装饰物需要能干净分层**：为了实现"换装系统"，角色形象需要能与服装、配件、场景分离处理，边缘干净（避免写实毛发边缘抠图脏），预留"基础形象+可替换配件"的图层结构
3. **小尺寸可辨识性**：角色会出现在小图标、头像等小尺寸场景，需保证在缩小状态下轮廓依然清晰不糊

### 3.4 全局UI视觉统一规范 ⚠️（发现问题：已产出资源尚未贯彻到全局UI，是当前"风格混乱"的根因）

**问题诊断**：目前App首页出现"两套设计语言打架"的情况——底部导航栏用了高细节写实插画图标，但页面其他部分（顶部状态栏、渐变卡片、任务列表、按钮）仍是原来的通用扁平风格（紫色渐变、白色圆角卡片、彩色emoji图标）。两者的色彩体系、细节程度、图标外形都不统一，导致整体观感割裂。

**核心原则：写实插画资源要分层使用，不能不分场合地全部套用**

| 场景 | 使用方式 |
|---|---|
| 头像、等级展示、装扮场景、成就徽章弹窗、品牌延展物料 | ✅ 用高细节写实插画（第3.2节产出的Ratty全套资源），细节越丰富越有沉浸感 |
| 底部导航栏、任务列表小图标、按钮内嵌图标等高频/小尺寸/需要快速识别的场景 | ❌ 不要用写实插画，改用**简化线性/剪影图标**（统一线条粗细、统一容器形状和尺寸），保留品牌色但去掉复杂细节 |

这是通用UI原则，不止HabitRat适用——包括《原神》《明日方舟》这类重美术产品，导航栏也都用极简图标，写实插画留给大展示位。

**全局配色 CSS 变量（需应用到整个App，不只是Ratty素材本身）：**

```css
:root {
  --ink: #2D3340;      /* 深色背景基调 / 深色文字 */
  --steel: #5C6F8E;    /* 蓝灰主色，替代原紫色系 */
  --leather: #A38F7A;  /* 皮革/木质中性色，中性边框/次要元素 */
  --gold: #C89D4A;     /* 金色点缀，替代原橙色/红色高亮 */
  --glow: #4FC3FF;     /* 发光蓝，核心识别色，用于进度条/强调点 */
  --paper: #F6F1E6;    /* 页面背景，暖米白，替代冷白/浅灰背景 */
}
```

**具体替换对照（改造现有页面时逐项对照）：**

| 现状元素 | 替换方向 |
|---|---|
| Header 紫色渐变卡片 | 改为 `--ink` → `--steel` 的深蓝灰渐变，边框用 `--gold` 细线收边 |
| 进度条橙色填充 | 改为 `--gold` → `--glow` 渐变 |
| 今日已兑换等强调数字（红色） | 统一到 `--gold` 或 `--steel`，避免和"危险/错误"语义色混淆 |
| 任务卡片图标（🍳💧🧼等generic emoji） | 改为线性 SVG 图标（描边风格），颜色用 `--steel`，背景用浅色色块 |
| 底部导航栏（当前4个写实插画图标） | 改为线性图标 + 统一圆角容器，选中态用 `--gold` 背景高亮，参考下方示意稿 |
| 页面整体背景（白/浅灰） | 改为 `--paper` 暖米白，与写实插画的暖色调呼应 |

**参考示意稿**：`HabitRat_首页_统一风格示意.html`（已提供给作者，包含完整的首页改造示例代码，可直接作为改造参照，Claude Code 可直接读取其中的 CSS 和 SVG 图标写法）

## 4. 装扮/成长系统（Royal Match式玩法，核心差异化功能）

参考 Royal Match / Homescapes 的"通关得星星→装饰场景"逻辑，替换现有"打卡攒金币→商店买单品"的交易式体验，改为"打卡解锁场景元素→场景逐渐变漂亮"的建造式体验。

### 4.1 场景系统
- 孩子可**选择初始场景风格**：树洞小屋、地下宫殿、海边别墅等（提供选择而非固定单一场景）
- 每个场景内分为若干区域/装饰位，随打卡获得的EXP逐步解锁
- **MVP阶段**：先做一个场景、15-20个装饰品验证效果，不要一次做多场景
- **后续大版本更新**：陆续增加新场景风格，作为持续拉动留存和用户期待感的运营手段

### 4.2 分层内容解锁机制（⚠️ 核心机制，务必保留）
- **日常打卡** → 解锁基础装饰
- **连续打卡里程碑** → 解锁稀有装饰
- **节日限定** → 未来增加节日限定款装饰（后续迭代）

### 4.3 角色与场景双线成长
- Ratty 本身随等级产生**形态变化**：从简陋疲惫 → 装备精良自信闪耀（见第3.2节）
- 场景变漂亮 + 角色变强，两条线同步进行，强化"好习惯让自己和周围都变好"的核心隐喻

## 5. 文案与措辞基调调整

现有文案偏低幼向，需要与视觉风格一起"长大"：

| 现状 | 建议方向 |
|---|---|
| "宝贝" | 直接用孩子的名字，或更中性称呼 |
| "今天也要加油鸭！" | 更简洁、有游戏感的激励语，减少幼态拟声词 |
| "习惯新手" 等称号 | 保留称号体系，但整体措辞向"任务/关卡/成就"游戏化语言靠拢 |
| 大量可爱emoji堆砌（🐹💰🎁） | 逐步替换为游戏化UI图标风格（徽章、勋章、装备图标），emoji仅作为点缀而非主要视觉语言 |
| "今日任务" / "连续打卡" / "金币" | 可考虑更有世界观感的包装，比如"每日任务"、"连击/Streak"、"晶石/能量石"等（需与角色世界观统一设计，非最终命名，仅方向参考） |

## 8. 首页布局与交互细节

### 8.1 头部固定区域压缩（解决"任务列表可视空间太小"问题）

问题：原设计头部固定区域（状态栏+英雄卡片+独立的"今日获得/今日兑换"卡+分段控件）占用空间过大，导致同屏只能看到2-3条打卡事项，用户需要频繁滚动。

**压缩方案：**
- 删除独立的"今日获得/今日已兑换"白色卡片，改为将"今日+X"数值合并显示在英雄卡片统计行对应项目下方（比如"已获得46"下面的小字"今日+0"）
- 头像从62px缩小到42px，等级/问候语/进度百分比整合为一行紧凑排布
- 统计行、分段控件内边距和字号整体收紧
- 效果：同屏可见任务从2-3条提升到约5条

**进阶优化（可后续迭代，非当前必做项）**：头部区域可做"滚动收缩"——用户下滑任务列表时头像/进度条区域自动缩小甚至隐藏，只留精简状态条。这是常见习惯类App做法，但需要额外滚动监听逻辑，实现成本高于纯压缩方案，建议基础版本上线后再迭代。

### 8.2 统计区域与"今日/周/月"切换的联动逻辑 ⚠️（重要，避免遗漏）

统计区域不是静态的，需要跟随顶部"今日任务/周/月"分段控件的选中状态动态切换，具体规则：

| 选中状态 | 统计行小字显示 | 是否显示"完成进度"行 |
|---|---|---|
| 今日任务 | "今日+X"（当日获得/兑换量） | 否——今日视图本身就是任务列表，不需要额外的完成度提示 |
| 周 | "本周+X"（本周获得/兑换量） | 是——在任务列表上方显示"本周 X/Y 已完成"+进度条，帮助用户在聚合任务列表中快速定位完成情况 |
| 月 | "本月+X"（本月获得/兑换量） | 是——同上，显示"本月 X/Y 已完成"+进度条 |

**实现要点**：切换分段控件时，需要同时更新（1）统计行的"今日/本周/本月+X"文案和数值 （2）完成进度行的显示/隐藏状态、文案（本周/本月）、进度数值和进度条百分比。三者必须联动更新，不能只切换分段控件的选中样式而不更新其他区域，否则会出现"标签切换了但数字没变"的问题。

**参考示意稿**：`HabitRat_首页_统一风格示意.html`（v2版本已加入可点击交互，点击"今日任务/周/月"可直接看到上述联动效果，包含完整的HTML/CSS/JS实现，Claude Code可直接参考其中的交互逻辑代码）

## 9. 打卡数据模型升级 + 行为分析功能 ⏸️（已评估方案，暂缓实施）

> **状态说明**：本节完整设计方案已确定（见下），但实施评估后作者决定暂缓——涉及历史数据兼容处理，改动风险和当前收益不对等，且不是当前刚需功能。待后续需要详细设计"延迟完成"相关体验、或历史数据量变得更值得投入时再启动。以下内容作为方案存档，重新启动时直接参考，无需从头设计。

### 9.1 问题：当前"完成/未完成"二元记录丢失了关键行为数据

孩子延迟完成任务（比如晚了半小时吃早饭）目前被记录为和"完全没做"一样的 ❌，这类数据丢失导致后续无法做有意义的行为分析和正向激励。

### 9.2 数据模型调整方案

打卡时需要记录**实际完成时间戳**，而不是只存布尔值，再用"实际时间 vs 截止时间"动态判断状态：

| 状态 | 判断逻辑 | 展示 |
|---|---|---|
| ✅ 按时完成 | 实际打卡时间 ≤ 截止时间 | 绿色对勾 |
| 🟡 延迟完成 | 实际打卡时间 > 截止时间，但当天完成了 | 黄色/橙色标记，区别于红叉 |
| ❌ 未完成 | 当天结束时仍未打卡 | 红叉 |

⚠️ **这是数据结构层面的改动，需要和之前提到的"架构体检"一起排查**——历史数据（只有布尔值、没有时间戳）需要考虑兼容和迁移方案，越晚处理成本越高。

### 9.3 奖励规则（当前阶段决策，非永久方案）

- **延迟完成：暂不给 EXP/金币奖励**（作者决定：产品早期阶段先偏严格，避免打卡标准过于松弛；后续可根据实际使用效果调整为"给部分奖励"）
- **连续打卡（Streak）判定**：延迟完成**仍计入连续打卡天数**，不因"晚了"而打断streak——streak机制强化的是"持续性"而非"完美时间管理"，两者不应混在一起判定
- **备注**：延迟完成的奖励比例，未来如果要放开，建议做成家长可调整的参数（而非固定值），因为不同家庭对"准时"的重视程度不同

### 9.4 行为分析功能设想（"成长"页可扩展方向）

基于按时/延迟/未完成三态数据，可以做的分析内容：

- **趋势图**：近7天/30天的按时完成率变化，直观展示"在变好"
- **分习惯诊断**：哪个习惯按时率最高（值得表扬）、哪个习惯经常延迟或跳过（可能是时间设置不合理或难度过高，提示家长调整而非一味归咎孩子）
- **时间规律洞察**：比如"周末完成率比工作日低"，帮家长发现规律而非单纯批评
- **对比激励**：本周 vs 上周的正向对比，哪怕只是"延迟完成率下降了"也值得展示
- **文案基调**：延迟完成要用鼓励性语言（比如"虽然晚了一点，但你做到了！"），避免制造挫败感
