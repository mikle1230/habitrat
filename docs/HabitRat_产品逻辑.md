## 1. 产品概述

**HabitRat（好习惯大冒险）** 是一个面向孩子的习惯打卡 Web 应用，核心机制是「打卡获得经验值/金币 → 升级 → 装扮吉祥物/场景」。

| 维度 | 内容 |
|---|---|
| 目标用户 | 10-12 岁（小学高年级）为主，理想覆盖到初中生 |
| 产品定位 | 不做「低幼可爱」风格，做这个年龄段孩子也愿意用的、有质感的「酷」产品 |
| 当前阶段 | 小范围家庭试用中，产品深度打磨期 |
| 商业定位 | 作者认真经营的副业方向，非纯个人玩具 |
| 部署 | Vercel（纯前端单页应用，无构建步骤） |

**核心循环**：每日打卡 → 获得 EXP / 金币 → 升级 → 解锁 Ratty 的装饰、配饰、场景。

**已有核心功能**：打卡记录（今日 / 周 / 月视图）、EXP 与金币双激励、等级系统、成就系统、场景装扮、奖励商店、家庭码跨设备同步、家长 PIN + 密保找回、数据备份恢复、桌面打印周表。

**核心差异化**：不是「个人自我管理」（Habitica 的模式），而是「**家长辅助、孩子游戏化打卡**」——家长是关卡设计师和审批人，孩子是玩家。游戏化程度对标 Habitica，但审批 / 监督关系保留。

---

## 2. 核心设计原则（产品策略）

10-12 岁及以上孩子的关键心理：**抗拒「幼态」设计**，「这是给小孩玩的」是这个年龄段最忌讳的评价。因此：

- ❌ 避免：大量可爱 emoji 堆砌、「宝贝」这类称呼、「加油鸭」式儿童化语气、纯卡通扁平萌系画风
- ✅ 追求：游戏化的「任务 / 关卡 / 成就」语言、精致有质感的视觉风格、通过努力「变强 / 变自信」的成长反差感

**成长反差感**是核心情感抓手：Ratty 自身从简陋疲惫（Lv.1）成长为装备精良、自信闪耀（Lv.MAX），场景从空房间逐渐变漂亮——强化「好习惯让自己和周围都变好」的隐喻。

## 3. 吉祥物设定

- **名字**：小瑞（Ratty）
- **角色**：习惯教练 & 成长伙伴
- **性格**：坚韧、善良、责任心强、乐于助人
- **爱好**：记录目标、帮助朋友、收集徽章
- **口头禅**：「再来一次！」「我能做到！」「一点点就好」
- **背景故事**：一只经历过风雨、依然坚持的小老鼠，背着装着「习惯清单和梦想」的小书包，帮助孩子养成好习惯，自己也一点点变得更强大

> 视觉形象与成长阶段设定见风格设计文档 §3。

## 4. 游戏化经济系统

### 4.1 双货币模型

| | 经验值 EXP | 金币 Coin |
|---|---|---|
| 获得方式 | 每次打卡达标，按习惯配置的 `expValue` 发放 | 同时发放，按习惯配置的 `coinValue`，权重可独立于 EXP |
| 会不会被扣/花 | **永远不会**，只增不减，也不能被「花掉」 | 会：兑换现实奖励、犯错扣分都动这个 |
| 驱动什么 | 等级 / 称号，达到等级门槛时自动免费解锁装扮 | 消耗型奖励商店 |
| 心理作用 | 「努力的历史记录」，不会因犯错被抹去 | 「可支配的现实零花钱」，会被惩罚扣减 |

**发放规则：**
- 每个习惯配置两个数值字段：`expValue`、`coinValue`，权重可以完全不同——比如「阅读」这类更想鼓励「坚持」本身的习惯，可给更高的 `expValue`（升级更快）而 `coinValue` 正常甚至偏低（避免零花钱通胀）。默认两者相等，家长可调。
- 连续打卡达标那一刻，EXP 和 Coin 一起结算发放。
- 家长手动加分（`btnBonus`）：默认只加 Coin。UI 提供「额外加经验值」勾选项，默认不勾。
- 手动扣分（`btnDeduct`）：只扣 Coin，**绝不扣 EXP**。这是硬规则，任何代码路径都不得扣减 EXP。

### 4.2 等级 / 称号系统

- **等级曲线**：`level = floor(sqrt(totalExp / coefficient)) + 1`，平方根曲线（前期升级快、及时反馈；后期需要更多积累）。`coefficient` 为家长可调系数（默认 50），按「孩子一个暑假大概升 5-8 级」反推节奏。
- **等级门槛对应 EXP**：`getExpForLevel(level) = coefficient × (level-1)²`。
- **称号**：每个等级对应一个称号，家长可在设置页编辑文案。新版五阶称号见风格设计文档 §3.1。
- **升级解锁装扮**：升级到某等级门槛，自动免费解锁一件新装扮物品（服饰 / 伙伴 / 背景之一），直接进入「衣柜」，不花任何东西。
- **进度条 UI**：当前等级 → 下一等级还差多少 EXP，比纯数字更有游戏感。

### 4.3 奖励商店：两类分开

- **消耗型（花 Coin）**：兑换项目全部归此类——游戏时间、零食、外出等现实向兑换。逻辑：选择项目 → 扣 Coin。
- **收藏型（升级免费解锁，不花钱）**：等级解锁的装扮物品展示，只读显示「已解锁 / 未解锁」，无兑换交互。
- **两类必须分开展示**（不同 Tab / 分区、视觉区分），避免孩子混淆「这个到底要不要花钱」。

### 4.4 装扮玩法

- 单独「Ratty 的家」场景，展示当前小老鼠形象（默认形态 + 已装备的服饰 / 伙伴 / 背景）。
- 装扮物品**不能购买，只能靠升级自动解锁**，全程免费。
- 已解锁物品可在「衣柜」里自由切换穿戴 / 更换背景，不消耗任何东西。
- 首次上线 6-10 件起步验证效果，不做完整服装系统。

### 4.5 金币银行 / 利息（未来方向，暂缓）

攒着金币不花时按周期产生利息，鼓励延迟满足 + 朴素理财启蒙。落地前需敲定：结算周期、利率定法、是否设上限、与「扣分惩罚」的交互（如结息日被扣分利息怎么算）。等双货币 + 装扮玩法验证完再单独设计。

## 5. 打卡系统

### 5.1 记录操作

| 操作 | 结果 |
|---|---|
| 点击 ○（待做） | → ✔ 完成 |
| 点击 ✔（已完成） | → ✗ 未完成 |
| 点击 ✗（未完成） | → ○ 恢复待做 |
| 点击 —（不适用） | 无反应，不适用日不可编辑 |

### 5.2 不适用日（`noschool`）

- `noschool` 类型的习惯（如吃午饭）**仅限节假日和寒暑假**显示，工作日自动隐藏。
- 寒暑假日期在设置里配置，系统自动判断当前日属于「工作日 / 节假日 / 寒暑假」（顶部展示模式标签）。

### 5.3 连续规则

系统自动计算，无需手动操作：
- 每天 ✔ → 连续计数 +1
- 连续计数 ≥ 目标次数 → 一次性发 EXP + Coin → 连续清零重新计数
- 出现 ✗ → 连续中断 → 归零重计
- 有豁免投票且通过 → 连续保留

### 5.4 断连豁免投票

- **触发**：某天某习惯出现 ✗，但有特殊原因，不想让连续中断。
- **流程**：点 🗳 按钮 → 填写申请理由 → 家庭成员逐一投票 → **需全部同意**才可通过。
- **结果**：通过后连续保留，不计为断连；历史投票记录可查。
- **为什么是这个设计**：这是「家长辅助」定位的核心——孩子不因不可抗力被惩罚，但豁免需要家人共同监督。

### 5.5 节假日 / 寒暑假判断

- 法定节假日 + 调休工作日：每年维护（`HOLIDAYS_2026` / `MAKEUP_2026` 之类的年度表）。
- 寒暑假：设置页可增删日期区间（默认暑假 7/1-8/31、寒假 1/18-2/28）。
- 假期内适用「假期细则」（比工作日宽松）。

## 7. 设置与安全

### 7.1 设置模块（按使用合理性排序）

1. **🔐 同步与安全**：家长 PIN、密保问题、跨设备同步
2. **👧 基础信息**：孩子名字
3. **📋 习惯**：习惯清单增删改（标题、连续天数门槛、EXP 值、Coin 值、生效星期）
4. **🏖 假期**：寒暑假日期区间
5. **💾 数据管理**：备份、恢复、导入导出

**所有设置自动保存**，无「保存设置」按钮。

### 7.2 家长 PIN 与密保

- **锁定策略**：设置页面默认对家长可用；设置 PIN 后整个设置页用 PIN 锁保护，孩子日常看不到家长配置。分享给朋友时初始不锁，设置 PIN 后自动启用锁。
- **PIN 设置**：输入需**两次确认**，避免误输入。
- **密保问题（忘记 PIN 找回）**：设置 PIN 时提示设置「密保问题 + 答案」；忘记 PIN 时通过密保问题验证后重置 PIN。未设密保又忘记 PIN 会被锁在设置外（需清 localStorage 重来，设计上可接受）。
- **每日解锁**：非今日的打卡记录修改需 PIN 验证。

### 7.3 数据备份

- 完整备份导出（JSON） / 恢复导入。
- 跨设备同步：数据存 localStorage + 云端（见 §9）。

## 8. 数据模型

数据结构按「未来能直接映射成数据库表」的标准设计，即使当前整块存 JSON：

```
family: { id: uuid, inviteCode: string, createdAt }
members: [{ id: uuid, name, role: 'guardian'|'child'|'viewer', totalExp: number }]
habitTemplates: [{ id: uuid, ownerMemberId: uuid, rewardTargetMemberId, title,
                   rule: { streakNeed, expValue, coinValue, activeDays }, archived: boolean }]
checkinLogs: [{ id, memberId, habitId, date, status: 'done'|'missed'|'na', effectivePoint: boolean }]
transactions: [{ id, memberId, type: 'earn_exp'|'earn_coin'|'spend_coin'|'deduct_coin'|'bonus_coin'|'bonus_exp',
                 amount, reason, createdAt }]
rewardItems: [{ id, kind: 'consumable'|'outfit', title, cost (仅 consumable), unlockLevel (仅 outfit) }]
```

要点：
- `level` 是派生值，不存储，运行时由 `totalExp` 计算。
- 习惯可 `archived` 停用而非删除，保留历史打卡记录。
- 支持「某人的习惯，奖励记到另一人账户」（`rewardTargetMemberId`）。
- localStorage key：`habitRat:v4`（旧版 `habitRatV4` 兼容读取）。
- **迁移准则**：字段命名与 ID 设计现在按「以后拆数据库表」的标准来，后续迁移时基本是摊平数组成表，不需要重新设计模型。

## 9. 技术架构与同步机制

### 9.1 架构

```
┌───────────────────┐   POST /api/habit-sync   ┌─────────────┐
│  浏览器(电脑/手机)  │ ───────────────────────→ │ Vercel API  │ → Upstash Redis
│  index.html        │                          │ habit-sync  │
│  localStorage 本地  │ ←─────────────────────── │             │
└───────────────────┘   GET /api/habit-sync     └─────────────┘
```

- 纯前端单页应用，无框架依赖，不参与构建。
- 所有操作先写入 localStorage，离线可用；后台 3 秒防抖后同步到服务端；其他设备刷新时自动拉取。

### 9.2 写入流程

```
用户操作 → saveData()
  ├── localStorage.setItem('habitRat:v4', ...)
  └── debounceSyncToServer()   ← 3 秒防抖
        → syncToServer() → getSyncData() 组装全部数据 → POST /api/habit-sync
```

### 9.3 读取流程

```
页面加载 → initSync() → loadFromServer()
  ├── GET /api/habit-sync?_t=时间戳（缓存破坏）
  ├── 比较服务端 _serverUpdatedAt 与本地最后更新时间
  └── 服务端更新 → 覆盖内存变量 → 写入 localStorage
```

### 9.4 关键要点

| 规则 | 说明 |
|---|---|
| 时间比较基准 | 用服务端写入时生成的 `_serverUpdatedAt`，不用设备本地时间，避免各设备时钟差异 |
| 加载后不回传 | `initSync()` 中调用跳过自动回传，防止加载后重新上传引发竞争 |
| 缓存破坏 | GET 加 `?_t=时间戳` + `Cache-Control: no-cache` |
| 防抖 | 变更后 3 秒才推送，批量操作只推送一次 |
| 幂等写入 | 整量替换（非增量），每次上传完整数据 |
| 同步状态指示 | 顶栏 ✅ / ⚠️ / 🔄，仅在 `syncToServer()` 时更新 |

### 9.5 离线使用

- 没网时所有操作正常（本地存储）；网络恢复后自动同步。
- PWA 离线打开不白屏（缓存静态资源）。

## 10. 首页交互逻辑

### 10.1 头部区域压缩（解决「任务列表可视空间太小」）

- 删除独立「今日获得/今日兑换」卡片，合并为英雄卡片统计行对应项目下方的小字（如「已获得 46」下面「今日 +0」）。
- 头像、等级/问候语/进度、统计行、分段控件整体紧凑排布，同屏可见任务从 2-3 条提升到约 5 条。
- **进阶（后续迭代）**：头部「滚动收缩」——下滑任务列表时头像/进度条自动缩小隐藏，只留精简状态条。

### 10.2 统计区域与「今日 / 周 / 月」切换联动

统计区域必须跟随顶部分段控件动态切换，三者联动更新，不能只切选中样式：

| 选中状态 | 统计行小字 | 是否显示完成进度行 |
|---|---|---|
| 今日任务 | 「今日 +X」（当日获得/兑换量） | 否——今日视图本身是任务列表 |
| 周 | 「本周 +X」 | 是——任务列表上方显示「本周 X/Y 已完成」+ 进度条 |
| 月 | 「本月 +X」 | 是——同上 |

切换时需同时更新：(1) 统计行「今日/本周/本月 +X」文案和数值；(2) 完成进度行的显示/隐藏、文案、进度数值和百分比。

### 10.3 打卡反馈动效（低成本高优先级）

- 打卡成功：彩带 / 星星飘落动画、音效
- 连续打卡：随天数增加的「火焰」或「能量」进度图标
- 升级：光效 + 音效 + Ratty 庆祝小动画
- 目的：低成本提升「专业感」，缓解「AI 味重、体验粗糙」的第一印象

### 11.1 延迟完成三态 + 行为分析

**问题**：当前「完成/未完成」二元记录丢失关键行为数据——孩子晚半小时吃早饭被记为和「完全没做」一样。

**数据模型调整**：打卡记录实际完成时间戳，用「实际时间 vs 截止时间」动态判断：

| 状态 | 判断逻辑 | 展示 |
|---|---|---|
| ✅ 按时完成 | 实际打卡时间 ≤ 截止时间 | 绿色对勾 |
| 🟡 延迟完成 | 实际 > 截止，但当天完成 | 黄色/橙色标记 |
| ❌ 未完成 | 当天结束仍未打卡 | 红叉 |

**奖励规则（当前决策）**：延迟完成暂不给 EXP/金币奖励（早期偏严格）；延迟完成**仍计入**连续打卡天数（streak 强化「持续性」而非「准时」）。未来放开时建议做成家长可调参数。

**行为分析**（成长页扩展方向）：近 7/30 天按时率趋势、分习惯诊断、时间规律洞察（如「周末完成率比工作日低」）、本周 vs 上周正向对比。文案用鼓励性语言（「虽然晚了一点，但你做到了！」）。

⚠️ 这是数据结构层面改动，涉及历史数据兼容迁移，风险与当前收益不对等，故暂缓。
