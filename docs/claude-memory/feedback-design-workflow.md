# 设计工作流反馈

用户明确纠正过多次关于「如何做设计」的工作方式，以下为可复用的偏好：

## 先出方案，确认后再动手

- **改动 UI/UX 前先提方案讨论，确定后再动手**（「先出方案，确定好再动手」「你看以后咱们再开始」）。用户会逐条点评建议，批准后才实施。
- 大改动习惯分阶段推进、先备份。

## 拒绝「没有设计感的排版微调」

- 用户质问过 **「你确定你调用了设计能力吗？」**——反复调间距/宽度/位置不是设计，是排版；越改越难看。
- **应调用 UI/UX Pro Max 等设计 skill 给出有依据的设计方案**（如 Claymorphism 软陶风格），先想清楚视觉语言再改代码。
- 改砸了要及时止损：**回退到最初可用版本 / 线上版本**，而不是继续在错误方向上微调（「还不如第一版了」「参考一下线上的版本」）。

## 设计感与实用性并重

- 设计**不能为了精简而精简**：原有大区块更易点击，交互优先；视觉层次要清楚、信息有主次。
- 保留现有色调，可以试用新布局，**不行就回退**。
- 功能不要删，只是优化表达方式（「不是要删内容，而是视觉层次和信息组织」）。

## 沟通细节

- 用户用浏览器实测并给出**非常具体的反馈**（元素位置、像素级、emoji 是否显示）；回应需可验证、可复现。
- 用户会临时切模型/要求换模型重试看图，注意当前模型能力。
- 产品逻辑层面用户看重**边界与漏洞设计**（如兑换退回的「白嫖循环」），讨论方案时应主动分析风险边界。
