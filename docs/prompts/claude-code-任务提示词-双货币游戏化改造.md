# 任务：把 HabitRat 改造成"双货币游戏化经济系统"，并让习惯清单/家庭结构可配置

## 背景

HabitRat（habitrat.vercel.app）目前是一个亲子习惯打卡工具：家长审批孩子的打卡，达标获得积分，积分可以兑换奖励或被扣除。已经有真实的跨设备同步（Vercel KV/Upstash，按家庭码分区）、JSON 备份恢复、家长 PIN 权限。

**这次的目标**：把它从"一个人的家庭工具"升级成"可以分享给周边人使用的通用版本"，核心是引入游戏化的双货币经济模型，并把之前写死的习惯清单/家庭成员改成可配置。这次**不**做账号密码体系、不做数据库迁移（继续用现在的 KV JSON 存储，但字段设计要为以后拆表做好准备）、不做完整 RPG 角色装备、不做家庭组队功能——这些留到下一阶段。

## 核心设计原则（务必先理解，再动手改代码）

**双货币分离，这是这次改造最重要的一条规则**：
- **EXP（经验值）**：每次打卡达标获得，**永远只增不减**——不会因为兑换消耗、犯错扣分而减少。它只驱动"等级"。
- **Coin（金币）**：真正能花的钱，兑换奖励会扣、犯错惩罚会扣。
- **硬性规则：任何"扣分"操作都只扣 Coin，绝不能扣 EXP。** 家长手动加分默认只加 Coin；如果要额外奖励努力本身，UI 上给一个"同时奖励 EXP"的勾选项，默认不勾选。

## 具体任务

### 1. 数据模型改造（先做这个，后面的功能都依赖它）

把现有的扁平结构改造成下面的形状（继续存在 KV 里的一整块 JSON，但内部结构要按这个来，方便以后拆数据库表）：

```
family: { id: uuid, inviteCode: string, createdAt }
members: [{ id: uuid, name, role: 'guardian'|'child'|'viewer', totalExp: number }]
habitTemplates: [{ id: uuid, ownerMemberId: uuid, title, rule: { streakNeed, expValue, coinValue, activeDays }, archived: boolean }]
checkinLogs: [{ id, memberId, habitId, date, status: 'done'|'missed'|'na', effectivePoint: boolean }]
transactions: [{ id, memberId, type: 'earn_exp'|'earn_coin'|'spend_coin'|'deduct_coin'|'bonus_coin'|'bonus_exp', amount, reason, createdAt }]
rewardItems: [{ id, kind: 'consumable'|'collectible', title, cost (仅consumable), unlockLevel (仅collectible) }]
```

- 现有数据（现在线上真实存在的家庭数据）需要写一个迁移脚本，把旧结构转换成新结构，**不能丢数据**：现在的单一 `points`/`checks`/`effectiveLog` 要拆分映射到 `totalExp` + `transactions`（earn_coin 类型）+ `checkinLogs`。旧的 `HABITS` 写死数组、`FAMILY` 写死数组，迁移时转换成对应家庭的 `habitTemplates`/`members`。
- 迁移逻辑要幂等（重复跑一次不会出问题），并且在真正切换前，先跑一遍迁移 dry-run 输出结果给我看，我确认没问题你再让它生效。

### 2. 打卡结算逻辑：从单一积分改成双货币结算

- 每个习惯项目的配置里加 `expValue` 和 `coinValue` 两个字段（设置页里让家长可以分别填，默认两者相等）。
- 连续打卡达标那一刻（复用现有的 streak 判定逻辑），同时写入一条 `earn_exp` 和一条 `earn_coin` 交易记录，分别累加到 `totalExp` 和可用 Coin 余额。
- 手动加分按钮（原 `btnBonus`）：默认只产生 `bonus_coin`，加一个可选勾选框"同时奖励额外经验值"，勾选时才额外产生 `bonus_exp`。
- 手动扣分按钮（原 `btnDeduct`）：只产生 `deduct_coin`，代码里要确保任何路径都不会调用扣减 `totalExp` 的逻辑（这是硬规则，review 时特别检查这一点）。
- 兑换积分逻辑：改成只消耗 Coin，判断余额也只看 Coin 余额，不涉及 EXP。

### 3. 等级 / 称号系统

- 等级计算公式：`level = floor(sqrt(totalExp / 50))`，作为默认参数放在设置里（家长可调系数，方便控制"孩子一个暑假大概能升几级"的节奏）。
- 每个等级对应一个称号，家长可以在设置页编辑称号文案（提供 8 个等级的默认称号作为初始模板，比如 Lv.1"习惯新手" 到 Lv.8 之类，具体文案你可以自己起一版有趣的）。
- 界面上加一个"成长"视图（可以放进现有的 Tab 导航里）：显示当前等级、称号、进度条（当前 EXP 距离下一级还差多少）。
- 每个等级解锁一个"收藏型内容"（先做简单的：一个 emoji 徽章 + 一句解锁文案即可，不需要做真正的图片素材/装备系统），升级时自动加入该成员的"收藏"列表，不消耗 Coin。

### 4. 奖励商店拆分成两类

- 现有的"兑换项目"列表全部归为 `kind: 'consumable'`，字段从 `points` 改名 `cost`（对应 Coin），逻辑基本复用现有兑换流程。
- 新增 `kind: 'collectible'` 类型，展示等级解锁的收藏内容，只读展示"已解锁/未解锁"状态，不需要交互兑换。
- 商店 UI 上这两类要用不同的视觉标签区分（比如"🛍️ 兑换"和"🎁 收藏"两个分区或 Tab）。

### 5. 习惯清单 / 家庭成员可配置

- 设置页加"习惯管理"区块：家长可以增删改每个成员的习惯项目（标题、连续天数门槛、EXP 值、Coin 值、生效星期），替代现在写死的 `HABITS` 数组。删除习惯不要真删数据，标记 `archived: true`，保留历史打卡记录。
- 设置页加"家庭成员管理"：家长可以增删成员，指定角色（guardian/child/viewer），替代现在写死的 `FAMILY` 数组。至少要支持 1-4 个孩子（不要假设只有一个孩子）。

### 6. 邀请方式从"输入 6 位码"升级成邀请链接

- 生成形如 `https://habitrat.vercel.app/join/{inviteCode}` 的邀请链接，打开后自动带出"加入这个家庭"的确认流程（复用现有的家庭码加入逻辑，只是入口从"手动输入"变成"点击链接自动填入"）。
- 家庭码/邀请码支持在设置页一键重置（重置后旧链接失效）。
- 保留手动输入邀请码作为备选方式（不是所有分享场景都能点链接，比如口头告诉朋友）。

### 7. 免责声明

- 在设置页或首次加入家庭时，加一句简短提示："这是一个个人开发的小工具，数据存储在开发者的服务器上，请不要输入真实姓名以外的敏感个人信息。" 不需要做成正式的隐私政策弹窗，一句话提示即可，这次只是把丑话说在前面。

## 明确不要做的事

- 不做账号密码/OAuth 登录系统。
- 不迁移到 Postgres 数据库（继续用 KV，但第 1 条的数据结构要为以后迁移铺路）。
- 不做完整 RPG 角色/装备系统，收藏型解锁这次只做 emoji+文案级别。
- 不做家庭组队/共同任务功能。
- 不做多孩子之间的排行榜/对比功能。

## 验收标准

1. 现有家庭的旧数据经过迁移后，历史打卡记录、积分余额（映射到 Coin）完整无损。
2. 犯错扣分之后，孩子的等级/称号不会下降。
3. 家长可以在设置页自由增删习惯项目和家庭成员，不需要改代码。
4. 一个新家长打开邀请链接，能顺畅加入家庭，不需要手动输入邀请码。
5. 兑换商店里"消耗型"和"收藏型"视觉上能明显区分，不会让孩子误以为收藏品要花钱。
